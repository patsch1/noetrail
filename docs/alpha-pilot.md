# Small alpha pilot

Run this after the six gates and installed-wheel acceptance pass. Start with
three to five volunteers using disposable synthetic data. Recruitment, release
publication and access to participants' private vaults are maintainer decisions;
this document sends no invitations and grants no access.

## Session (30–45 minutes)

1. Follow the checkout installation and quickstart without coaching. Record
   time until the first successful MCP search, OS, Python and client version.
2. Capture a note, attach a synthetic image, and retrieve both from the client.
3. Import a small synthetic Markdown/Obsidian sample twice. Explain skipped
   duplicates and inspect an unresolved relationship.
4. Ask five questions: exact title, German paraphrase, another language,
   a historical relation and a fact deliberately absent from the sample.
   Record whether the agent grounds its answer in the right entry, retries
   appropriately, or falsely claims knowledge/absence.
5. Correct a note with a revision check, preview a duplicate merge, then apply
   it only if the preview describes the intended result. Inspect trash.
6. Run a saved view over a custom type. Restore data and config onto new roots
   and verify that the view, relation and attachment still work.

## Record per task

Record success without help, time, number of agent tool calls, misleading
answers, understandable error messages and the smallest synthetic reproduction.
Use an anonymous participant label. Do not collect original notes, screenshots
of private content, credentials or full client logs. Keep only consented,
redacted observations; convert any issue into synthetic data before filing it.

## Exit decision

Every participant should complete capture and retrieval; at least four of five
(or all three in a three-person pilot) should finish setup without intervention.
There must be no observed data loss, silent mutation conflict or fabricated
answer to the deliberately absent fact. Every restore exercise must preserve
the selected IDs, revisions, pack, view and attachment bytes.

These are acceptance goals, not claimed results. Review failures first, record
the top three recurring usability problems, and select the next release work
from those observations and the question-suite categories. Rerun failed tasks
after fixes before expanding the pilot. No version number or publication is
changed automatically by passing this checklist.

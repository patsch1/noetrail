# Noetrail 0.11.0a1

This is the first alpha of the `0.11.0` line. Its only change is the removal
of the three compatibility shims under `tools/`, announced for `0.11.0` since
the first public alpha. That breaks a deployment that still invokes one of
those paths. The current core schema is 12; no migration is needed from
0.10.0a7. The index format is unchanged, and there is no new runtime
dependency.

## Changes

- The path shims are removed. Each only put `src/` on the import path and
  called the same entry point that every install already exposes:

  | Removed path | Console command | Module form |
  | --- | --- | --- |
  | `tools/know.py` | `noetrail` | `python3 -m noetrail.cli` |
  | `tools/knowledge_mcp.py` | `noetrail-mcp` | `python3 -m noetrail.mcp` |
  | `tools/bookmark_fetch_mcp.py` | `noetrail-bookmark-fetcher` | `python3 -m noetrail.bookmark_fetcher` |

  The module form works from an installed package, or from a checkout with
  `src/` on `PYTHONPATH`.
- What [ADR 0002](../adr/0002-noetrail-name-and-compatibility.md) keeps
  until a major-version decision stays: the `knowledge`, `knowledge-mcp` and
  `knowledge-bookmark-fetcher` console aliases, the `KNOWLEDGE_*` root
  variables, the `~/.config/knowledge` fallback, the former installed
  built-ins path fallback, and the ZeroClaw MCP server key with its
  `knowledge__*` tool namespace.
- Stored entries, the core schema, the index, and the CLI and MCP surfaces
  are unchanged. The specification's usage examples now name the `noetrail`
  command, which the shim called anyway, so the format's meaning is unchanged.

## Install

```sh
uvx --from 'noetrail==0.11.0a1' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.11.0a1),
[PyPI](https://pypi.org/project/noetrail/0.11.0a1/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.11.0a1/).

## Upgrade and rollback

Before upgrading, find anything that invokes `tools/know.py`,
`tools/knowledge_mcp.py` or `tools/bookmark_fetch_mcp.py`, for example a
ZeroClaw MCP server `command`, a cron job or a wrapper script, and switch it
to the console command or module form above. Then select 0.11.0a1 and
restart the MCP process. A command that already uses `noetrail`,
`noetrail-mcp`, `noetrail-bookmark-fetcher` or a `knowledge*` alias needs no
change. Everything else behaves as in 0.10.0a7, and an existing index stays
valid and fresh.

Rollback reinstalls 0.10.0a7. No data or index changes in either direction,
so no migration and no index rebuild is needed.

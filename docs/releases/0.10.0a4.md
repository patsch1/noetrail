# Noetrail 0.10.0a4

This alpha lets agents enrich existing bookmarks without replacing personal
content and find entries containing stored images across all entry types.
It also documents the correct image-delivery settings for ZeroClaw Discord.
The current core schema is 12; no migration is needed when upgrading from
0.10.0a3.

## Changes

- `refresh_bookmark` accepts an entry ID, its current revision and the complete
  version-1 isolated fetcher reply as `envelope`. The CLI equivalent is
  `refresh-bookmark ID --expected-revision REVISION --metadata-file FILE`.
  Only missing page fields are filled, with origin `web`; only an unknown
  bookmark kind is classified. Title, existing metadata, tags, URLs and body
  are preserved. Retrieval status and time are copied even after failure.
- Envelopes must match the saved original or canonical URL. Stale revisions,
  malformed replies, extra personal fields and arbitrary provenance are
  refused. Identical repeats succeed without rewriting the entry.
- `search` and `retrieve` accept `has_attachment: true` or `false`; CLI uses
  `--has-attachment` or `--no-has-attachment`. An empty query finds image-bearing
  entries without requiring photo words in their titles. Existing search
  `attachment_count` and inventory `entries_with_attachments` / `attachment_count`
  are explained in MCP descriptions and the shipped knowledge prompt.
- ZeroClaw Discord v0.8.4 uses `discord_files` for incoming files and an absolute
  `[PHOTO:{path}]` delivery marker with no marker root. Matrix uses `matrix_files`
  and relative `[IMAGE:{path}]` markers with a workspace root. The setup guide
  and deployment example distinguish both channels.
- The supervised ZeroClaw profile keeps refresh in neither `always_ask` nor
  `auto_approve`, allowing an explicit session grant for a requested batch.

## Install

```sh
uvx --from 'noetrail==0.10.0a4' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.10.0a4),
[PyPI](https://pypi.org/project/noetrail/0.10.0a4/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.10.0a4/). GitHub also carries
checksums, the bill of materials and verifiable build provenance.

## Compatibility and limits

Python 3.11 through 3.14, the dependency-free runtime and schema 12 remain
unchanged. Refresh works on schema 10–12 entries; earlier schemas require an
explicit migration because they cannot persist field provenance. This tool
never migrates data automatically, fetches a URL or changes a bookmark's
identity. Mutation isolation and the 30-second process timeout remain in place.

Search filters apply before pagination and ranking fallbacks, with or without
the derived index. Attachment counts describe stored references, including a
blob referenced by several entries; they do not classify image contents or
count distinct photographs. Respect incomplete inventory reports and continue
search pages when requesting a complete listing.

## Upgrade and rollback

From 0.10.0a3, select the new package version. Existing ZeroClaw deployments
must separately update their shipped prompt, skill bundle and channel-specific
MCP arguments, then restart affected sessions. Confirm the ordinary supervised
approval path for refresh and test image delivery with synthetic data before
use. Package publication does not change a running cluster or model selection.

Rollback selects 0.10.0a3 again and removes `refresh_bookmark` and
`has_attachment` from callers using those new inputs. Enriched fields and their
origins remain readable by the previous alpha. For older vault schemas, retain
matching data and configuration backups before applying an explicit migration;
see [backup and restore](../backup-restore.md).

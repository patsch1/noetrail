# Noetrail 0.10.0a1

This is the first public alpha of Noetrail, a local-first Markdown
knowledge vault with narrow, host-independent AI-agent interfaces.

The [GitHub prerelease](https://github.com/patsch1/noetrail/releases/tag/v0.10.0a1),
[PyPI](https://pypi.org/project/noetrail/0.10.0a1/) and
[TestPyPI distributions](https://test.pypi.org/project/noetrail/0.10.0a1/)
are available with identical CI-built artifacts.

## Highlights

- dependency-free Python CLI and MCP servers for Python 3.11 through 3.14;
- portable Markdown entries, stable IDs, revision-checked mutations,
  reversible trash, and content-addressed private attachments;
- declarative, non-executable schema packs for built-in and user-defined
  types, with generated validation and MCP input schemas;
- built-in thoughts, memories, notes, media, places, products, recipes,
  experiences, and bookmarks, including wishlists, reading state, ratings,
  photos, and cooking/visit/tasting history;
- `get_attachment` returns standard MCP image content, with an optional fixed
  outbox for host adapters that deliver workspace files;
- complete inventory aggregates and compact paginated search results with
  explicit totals and no silent result truncation;
- bounded one-call retrieval of several matching full entries, searchable
  grounded aliases, and declarative saved views for recurring filtered lists;
- schema-pack scaffolding and validation of uninstalled candidates before they
  enter an instance configuration;
- hybrid search combining literal substring matches and BM25 by default,
  with a verified optional index and conservative word-form candidates when
  the filtered result is empty. Tentative candidates are labelled; optional
  bounded excerpts preserve field provenance. A provider-neutral vector
  sidecar can rerank lexical results;
- bounded query reformulation in the ZeroClaw overlay for spelling mistakes,
  language changes and unsuccessful inferred filters;
- preview-first duplicate merge plans with revision checks, source retention
  in trash and rollback on write exceptions;
- Obsidian, Basic Memory, and generic Markdown imports with dry-run,
  provenance, link/attachment handling, and deterministic conflict reports;
- isolated bookmark metadata fetching with SSRF/DNS-rebinding protections and
  per-field provenance for untrusted web values;
- host-neutral skills and generic MCP documentation, plus a separate hardened
  ZeroClaw deployment overlay;
- initialize-era MCP compatibility and discovery-era `2026-07-28` support,
  with desktop, editor, and ZeroClaw protocol smoke profiles;
- synthetic CI, full-history publication audit, release consistency checks,
  reproducibility comparison, installed-wheel upgrade/restore acceptance,
  checksums, provenance attestation, and a CycloneDX SBOM.

## Compatibility

The current core schema is 12. Schema-8 through schema-11 built-in entries
remain readable during this alpha compatibility window. Migration is explicit:
`noetrail migrate --dry-run` previews every change before `--apply` writes
anything.

Schema 9 introduced the typed `attributes` envelope. Schema 10 added optional
per-field provenance. Schema 11 adds valid-time metadata and supersession to
individual relations: `valid_from`, `valid_until`, `recorded_at`, and
`superseded_by`. Older entries omit those optional fields without losing their
previous meaning. Schema 12 adds optional alternative names; its migration
only changes the version and never invents aliases.

`noetrail retype` can correct an entry filed under the wrong type while
preserving its stable ID, body, relations, attachments, lifecycle metadata,
and revision safety. It previews by default and is intentionally a local CLI
operation rather than an agent tool.

Legacy `knowledge`, `knowledge-mcp`, `knowledge-bookmark-fetcher`, and
`KNOWLEDGE_*` aliases remain available. New integrations should use the
`noetrail*` commands, `NOETRAIL_*` environment variables, and canonical MCP
tool names. A host may render a canonical name with its own server prefix.

## Known limits

The unindexed profile scans Markdown linearly. The documented measured profile
targets roughly 10,000 entries; storage latency and body size still matter.
The BM25 index is opt-in and rebuildable, not a second source of truth.
Semantic reranking requires vectors supplied by an external provider; Noetrail
ships no embedding model and opens no provider connection.

Obsidian, Basic Memory, and generic UTF-8 Markdown have supported importers.
Notion and Joplin exports still need source-specific normalization based on a
real export sample. The bookmark fetcher returns allowlisted metadata rather
than page bodies, so a recipe link does not automatically supply ingredients
or instructions.

Client smoke profiles verify protocol behavior, not vendor GUIs. A future
client release may require a compatibility update even when its JSON server
configuration is unchanged.

Retrieval is lexical, so an empty search does not establish that a fact is
absent. Broad paraphrases, translation and general typo correction depend on
the client agent. Word-form hits are tentative candidates whose full content
must support the answer. The locally authored synthetic diagnostics are not
an independent benchmark; see [retrieval evaluation](../retrieval-evaluation.md).

## Upgrade and rollback

Create and verify a complete data-root backup before migration. Stop writers,
run the dry-run, review every structural change, apply, and validate. After an
on-disk migration, rollback requires restoring the matching backup together
with the previous program release. Never lower `schema_version` manually.

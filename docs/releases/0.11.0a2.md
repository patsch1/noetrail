# Noetrail 0.11.0a2

This is the second alpha of the `0.11.0` line. It is about installing
Noetrail into an MCP host: the portable skills now ship in the wheel,
`noetrail connect` prints the server configuration for eight hosts in each
host's own format, and an opt-in `--write` merges that entry into a JSON
host's configuration file. The current core schema is 12; no migration is
needed from 0.11.0a1. The index format is unchanged, and there is no new
runtime dependency.

## Changes

- The six portable agent skills are installed with the wheel, below the
  environment's read-only `share/noetrail/skills`. Before, only the source
  distribution carried them, so a `uvx` or `pip` install had nothing to hand
  to a host. `noetrail skills path` prints where they are, and
  `noetrail skills export DIRECTORY` copies them into a host's skills
  directory. Neither command needs a vault. `export` refuses to overwrite an
  existing skill directory without `--force`, and never writes through a
  symbolic link or into a data or configuration root.
- `noetrail connect --client NAME` prints the MCP server entry for one host,
  with the instance's absolute roots, the file it belongs in, the host's
  skills directory with the matching `noetrail skills export` line, and the
  host's own `mcp add` line where it has one. `--launcher console|module|uvx`
  selects `noetrail-mcp`, the running interpreter with `-m noetrail.mcp`, or
  `uvx` pinned to the installed version; `--json` returns a fixed key set.
  Without root options it uses the instance `quickstart` created.
  `noetrail quickstart --client NAME` prints the same block in place of the
  generic one and adds it under `connect` in `--json`; `mcp_config` is
  unchanged.
- The supported hosts are:

  | `--client` | Host | Format |
  | --- | --- | --- |
  | `claude-code` | Claude Code | JSON |
  | `claude-desktop` | Claude Desktop | JSON |
  | `codex` | Codex CLI | TOML |
  | `cursor` | Cursor | JSON |
  | `gemini` | Gemini CLI | JSON |
  | `vscode` | VS Code (Copilot) | JSON |
  | `opencode` | OpenCode | JSON |
  | `zeroclaw` | ZeroClaw | TOML |

  Each block uses the host's own key and fields, for example `servers` for
  VS Code and `mcp` with `"type": "local"` for OpenCode. The text output names
  which hosts share `~/.agents/skills`, so one `noetrail skills export` there
  serves them all. The formats follow each vendor's documentation as of
  2026-10-30.
- `noetrail connect --client NAME --write` merges the entry into a JSON host's
  configuration file. It is a preview until `--apply` is added. An existing
  file is first copied to `FILE.<UTC timestamp>.bak`, every other server and
  key is kept, and a different existing `noetrail` entry is replaced only
  with `--force`. `--config-file PATH` chooses another file. It refuses the
  TOML hosts (Codex CLI, ZeroClaw), files that are not plain JSON, symbolic
  links, a host directory that does not exist, and any path inside a
  Noetrail root. `--json` adds a `write` object.
- Without `--write --apply`, `connect` writes nothing. Stored entries, the
  core schema, the index, the MCP tools and the existing CLI commands are
  unchanged.

See [Connecting an MCP client](../integrations/mcp-clients.md#connect-a-known-host)
for the full host table and the write rules.

## Install

```sh
uvx --from 'noetrail==0.11.0a2' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.11.0a2),
[PyPI](https://pypi.org/project/noetrail/0.11.0a2/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.11.0a2/).

## Upgrade and rollback

Select 0.11.0a2 and restart the MCP process. No configuration has to change:
an existing host entry keeps working, and an existing index stays valid and
fresh. To adopt the new commands, run `noetrail connect --client NAME` for
your host and `noetrail skills export` for its skills directory.

Rollback reinstalls 0.11.0a1. No data or index changes in either direction,
so no migration and no index rebuild is needed. A host file written with
`--write --apply` keeps its entry and stays valid; its backup sits next to
it. An entry written with `--launcher uvx` pins `noetrail==0.11.0a2` and keeps
launching that version until you change the pin. Exported skill directories
are plain files and stay where they were copied.

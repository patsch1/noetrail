# Noetrail 0.10.0a7

This is a performance alpha for the optional derived search index, plus two
conservative fallback stages for hybrid searches that would otherwise return
nothing. The current core schema is 12; no migration is needed from 0.10.0a6.
The index file format is unchanged, and there is no new runtime dependency.

## Changes

- The index freshness check, a stat of every vault file that runs on every
  indexed query and every refresh, slices the vault prefix instead of calling
  `os.path.relpath` per entry. At 50,000 synthetic entries on an Apple M1 Pro
  it drops from 374 ms to 217 ms. The signature digest is unchanged, so an
  existing index still verifies as fresh.
- The index refresh after a write costs in proportion to the change rather
  than the vault. A change set of at most max(64, 2 % of the live documents) is
  spliced into the stored index instead of decoding every document and
  encoding it again; larger change sets keep the previous path, which writes
  the same bytes. One capture at 50,000 synthetic entries on an M1 Pro drops
  from 782 ms to 340 ms, and the stat walk is now about two thirds of what
  remains. An index that already matches the vault is not rewritten, and
  `noetrail index rebuild` without `--full` then reports `"mode": "unchanged"`
  with `"bytes": 0`.
- [Limits and scaling](../limits.md) re-measures the BM25 and index cost on an
  Apple M1 Pro running macOS 27.0.1, with the vault on the internal SSD's APFS
  volume and CPython 3.15.0, median of three runs. At 50,000 entries a full
  build takes 7.4 s and 45.2 MB, the freshness check 201 ms, a one-entry
  refresh 320 ms, and an indexed BM25 query 359 ms. The index no longer
  doubles the cost of a capture; the per-file stat walk is the cost that still
  grows with the vault, and the [roadmap](../../ROADMAP.md) now names a
  different freshness strategy as the next scaling step.
- Hybrid search gains two last stages, each tried only when every earlier
  stage found nothing. First, a query word of six or more letters that opens
  or closes a word at least three letters longer in the entry (`Zugreise
  schlafen` finds "Nachtzugreise"; `match_kind: word_form`). Then, one-edit
  typos of body words of seven or more letters (`Mondarchvi` finds a note
  mentioning "Mondarchiv"; `match_kind: typo`). Both report the observed
  spelling in `matched_terms` and in explanations. See
  [ADR 0010](../adr/0010-body-typos-and-compound-components.md).
- On the locally authored 100-question diagnostic set, hybrid Recall@5 rises
  from 0.600 to 0.653, correct-empty answers stay at 24/25 and irrelevant
  results at 12. Nonempty results, the `substring` and `bm25` modes, the
  index, and the CLI and MCP wire shapes are unchanged. These are
  deterministic retrieval measurements; they do not measure the answers a
  client model writes from the results. See
  [retrieval evaluation](../retrieval-evaluation.md).

## Install

```sh
uvx --from 'noetrail==0.10.0a7' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.10.0a7),
[PyPI](https://pypi.org/project/noetrail/0.10.0a7/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.10.0a7/).

## Upgrade and rollback

Select 0.10.0a7 and restart the MCP process. An existing index stays valid
and fresh; no rebuild is needed. The new fallback candidates carry the
existing `word_form` and `typo` labels and appear only where a hybrid search
was previously empty, so nonempty results are unchanged and prompts that
already treat those labels as tentative need no change.

Rollback selects 0.10.0a6 without a data migration and without an index
rebuild, because neither the vault nor the index format changed. Searches
that only the new stages answered return empty again, and each index refresh
again decodes and re-encodes the whole stored index.

# Noetrail 0.10.0a3

This alpha improves retrieval of misspelled titles and lets callers combine
alternative wordings or translations in one bounded read.
The current core schema is 12; no migration is needed when upgrading from
0.10.0a2.

## Changes

- An empty hybrid search checks title and alias tokens for one insertion,
  deletion, substitution or adjacent transposition, after lexical and
  word-form candidates are empty. Candidates carry `match_kind: typo` and
  observed `matched_terms`; inspect their source bodies before answering.
- CLI `retrieve` accepts up to three additional `--query-variant` values;
  MCP uses `query_variants` alongside the original `query`. The tool fuses
  complete candidate sets, deduplicates entry IDs and reports each entry's
  matching query strings in `query_matches`.
- All variants share the existing ten-entry and 100,000-body-character limits,
  type/date restrictions, read lock and deadline. Noetrail does not generate
  translations or synonyms. The ZeroClaw knowledge prompt counts each string
  toward its existing four-query budget.
- README, installation instructions and MCP examples pin this alpha. The
  release process records the maintainer's authorization for routine alpha
  updates while retaining the protected PyPI environment review.

## Install

```sh
uvx --from 'noetrail==0.10.0a3' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.10.0a3),
[PyPI](https://pypi.org/project/noetrail/0.10.0a3/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.10.0a3/). GitHub also carries
checksums, the bill of materials and verifiable build provenance.

## Compatibility and limits

Python 3.11 through 3.14 and the dependency-free runtime are unchanged. Existing
single-query response shapes remain unchanged when no variants are supplied,
apart from the new, explicitly labelled typo candidates after an empty hybrid
search. Explicit substring/BM25 modes and nonempty earlier results retain their
behavior. Stored entries, schema packs and mutation isolation are unchanged.

Typo matching is limited to alphabetic title/alias tokens of 5–64 characters;
numeric and hash-like tokens are excluded. It does not fuzzy-match bodies or
establish that two names identify the same thing. Blank, equivalent, oversized
or NUL-containing batch strings are refused, as are duplicate IDs in different
candidate files. An empty result still cannot establish absence. Vector
reranking still does not expand candidate membership.

The existing 100-question synthetic engine diagnostic improves from 32/75 to
45/75 answerable questions found, retaining 12 irrelevant results and 24/25
correct empty responses. A further locally authored transfer set recovers all
14 positives and leaves six distractors empty. These are small diagnostic
sets, not an independent benchmark or proof of model answer quality or latency.
See [retrieval evaluation](../retrieval-evaluation.md).

## Upgrade and rollback

From 0.10.0a2, select the new package version; no data migration is required.
An existing ZeroClaw deployment must separately update its shipped knowledge
prompt to use the optional batch input. Releasing the package does not change
a running deployment or its model configuration.

Program rollback selects 0.10.0a2 again and removes `query_variants` from callers
that use it; the previous package does not accept that optional input. For an
older data schema, preview an explicit migration and retain matching backups
of data and configuration before applying it. Follow
[backup and restore](../backup-restore.md).

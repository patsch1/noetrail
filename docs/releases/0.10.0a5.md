# Noetrail 0.10.0a5

This alpha updates the Discord deployment guidance with a confirmed outbound
image-delivery result and separates it from the still-unverified inbound path.
Runtime behavior and dependencies are unchanged from 0.10.0a4.
The current core schema is 12; no migration is needed from 0.10.0a4.

## Changes

- ZeroClaw Discord v0.8.4 has been confirmed in a live chat to deliver an image
  inline from an absolute `[FILE:{path}]` marker. The setup guide, example
  profile and shipped agent prompt now use that form, with no marker root.
- Incoming image staging under `discord_files` remains unverified. The setup
  guide includes a synthetic upload check covering the adapter's actual staging
  directory, pending-attachment tokens and an approved revision-checked attach.
  Noetrail's inbox unit tests do not establish ZeroClaw adapter behavior.
- Matrix keeps `matrix_files` and relative `[IMAGE:{path}]` markers with its
  workspace marker root. Bookmark refresh and attachment discovery remain
  available as described in the [0.10.0a4 notes](0.10.0a4.md).

## Install

```sh
uvx --from 'noetrail==0.10.0a5' noetrail quickstart
```

The same CI-built wheel and source distribution are distributed through
[GitHub](https://github.com/patsch1/noetrail/releases/tag/v0.10.0a5),
[PyPI](https://pypi.org/project/noetrail/0.10.0a5/), and
[TestPyPI](https://test.pypi.org/project/noetrail/0.10.0a5/).

## Upgrade and rollback

No data migration is needed from 0.10.0a4. Select the new package version; a
running ZeroClaw deployment separately adopts the updated prompt and config
example, then restarts affected sessions. Use only the verified, agent-specific
inbox root when testing inbound images. Package publication changes no cluster
or live configuration.

Rollback selects 0.10.0a4. No data restoration or schema change is required for
this documentation update.
